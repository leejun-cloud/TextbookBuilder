# sync-ppt — 교재 ↔ PPT 동기화

교재 본문(`lessons/NN/approved.md` 또는 `draft.md`)이 정본이고, 거기서 만든 PPT가 나중에
따로 수정되며 어긋나는 경우가 있다(예: PPT에는 옛날 토론 질문이 남아 있음). 이 스킬은 둘을
대조해서 차이를 사용자에게 보여주고, 승인받은 항목만 `pptx_batch.py replace-map`으로
일괄 반영한다.

## ① 범위 확정

사용자에게 다음을 확인한다:
- 어느 교재/어느 과(들)인지 (예: `projects/<id>/lessons/03`)
- 어느 PPT 파일(들)을 대조할지 (폴더 또는 파일 목록)

**방향을 반드시 확인한다.** 기본 방향은 **교재가 정본** — 교재 기준으로 PPT를 고친다.
만약 사용자가 "PPT 쪽 질문이 더 최신이라 교재를 바꿔야 한다"고 하면, 이 스킬이 아니라
`lesson-updater`로 교재 파일을 수정하는 흐름으로 안내한다 (이 스킬은 PPT를 고치는 용도다).

## ② 추출

대조할 PPT들의 내용을 텍스트로 뽑는다.

```bash
python3 scripts/pptx_batch.py extract --format md <pptx 파일들...> --out-dir <임시폴더>/
```

## ③ 대조

교재 파일(`approved.md` 우선, 없으면 `draft.md`)과 각 PPT의 추출된 md를 읽고 비교한다.

**대조 대상**: 질문(적용/토론 질문), 성경 인용문, 핵심 문장·키워드, 제목.

**판정 기준**: PPT는 교재를 슬라이드 언어로 요약한 것이므로, 문장이 짧아지거나 표현이
간결해진 것 자체는 불일치가 아니다. **내용이 실제로 다른 경우만** 불일치로 잡는다 —
다른 질문, 다른 인용 구절, 다른 사실 관계 등.

**파일이 5개 이상이면** Agent 도구(subagent_type: general-purpose)로 파일별 대조를
병렬 실행한다 (한 메시지에 여러 Agent 호출을 담아 동시 실행).

각 비교 결과를 다음 항목으로 수집한다: `{ppt파일, 슬라이드 번호, 교재 버전 문구, PPT 버전
문구, 판정근거}`.

## ④ 제시 (승인 전 절대 수정하지 않음)

불일치를 표로 보여준다:

| 위치(파일/슬라이드) | 교재 버전 | PPT 버전 | 판정근거 |
|---|---|---|---|

사용자가 어떤 항목을 반영할지 확인받는다. **승인 전에는 어떤 파일도 건드리지 않는다.**

## ⑤ 반영

승인된 항목만으로 pairs.json 을 만든다: `find`는 **PPT의 현재 문구 그대로**, `replace`는
교재 문구(또는 아래 참고).

**교재 문구가 슬라이드에 넣기엔 너무 길면**, 교재 질문의 의미는 유지하되 슬라이드 길이에
맞게 축약한 replace 문구를 만든다 — 이 경우 ④의 표에 "축약 적용됨"이라고 표시해 사용자가
알 수 있게 한다.

```bash
python3 scripts/pptx_batch.py replace-map --map pairs.json <해당 pptx 파일들...> --dry-run
```

건수를 확인한 뒤 실제 반영한다:

```bash
python3 scripts/pptx_batch.py replace-map --map pairs.json <해당 pptx 파일들...> --out-dir 동기화_YYYYMMDD/
```

**"미발견"으로 나온 쌍이 있으면** 원본에서 문구가 정확히 일치하지 않았다는 뜻이다.
해당 슬라이드를 다시 확인해 사용자에게 수동으로 보고한다 (자동으로 재시도하지 않는다).

## ⑥ 보고

- 파일별 반영 건수 (쌍별 건수 포함)
- 출력 폴더 경로 (`동기화_YYYYMMDD/`)
- 원본 PPT는 전혀 수정되지 않았음을 안내
- 미발견 쌍이 있었다면 목록과 확인이 필요하다는 점을 함께 안내
