1과는 전체 교재의 기준본(기준이 되는 과)이다. 이후 모든 과가 1과의 구조와 스타일을 따르므로 대충 만들면 안 된다. 아래 단계를 순서대로, 생략 없이 수행한다.

> 사용자가 이미 완성된 1과 샘플을 제공하는 경우 이 스킬 대신 `/import-lesson1`을 사용한다.

## 1. 입력 확인

`projects/<project-id>/project.md`를 읽는다. project.md의 "특수 지침" 섹션을 반드시 읽고 따른다. `lessons/01/input.md`를 확인한다.

- 있으면 내용을 읽는다.
- 없으면 사용자에게 1과 주제와 핵심 내용 3가지를 묻고, 답변을 `lessons/01/input.md`에 저장한다.

## 2. 리서치 (필수, 생략 금지)

`projects/<project-id>/sources/`에 주 원천 자료가 있으면 리서치는 보조 용도로만 쓰고, 본문은 원천 자료에 근거해서 작성해야 함을 유념한다.

WebSearch로 다음을 조사한다.

1. 1과 주제 자체에 대한 배경 지식
2. 이 대상(연령·수준)을 위한 기존 교재/커리큘럼이 수업을 어떻게 구성하는지
3. 이 대상에게 효과적인 활동/질문 아이디어

조사 결과를 사용자에게 간단히 요약해서 보여준다. 이 단계를 건너뛰고 바로 구조를 제안하지 않는다.

## 3. 구조 후보 3안 제시 (필수, 생략 금지)

리서치를 바탕으로 서로 뚜렷하게 다른 수업 구조 후보 3개(안 A/B/C)를 제시한다. 표면적 차이(순서만 바꾸기 등)가 아니라 접근 방식 자체가 달라야 한다. 예: 스토리 도입형 vs 질문 주도형 vs 활동 중심형.

각 안마다 다음을 포함한다.

- 섹션 구성(순서)
- 각 섹션의 분량 배분
- 활동 방식
- 이 대상에게 왜 효과적인지
- 톤을 보여주는 짧은 예시 문장(샘플 스니펫)

AskUserQuestion으로 사용자가 하나를 고르거나 여러 안을 섞도록 한다. 사용자가 고르기 전까지 다음 단계로 넘어가지 않는다.

## 4. 초안 작성

lesson-writer 서브에이전트를 Agent 도구로 실행한다(subagent_type: "lesson-writer"). 다음을 전달한다.

- project.md 내용 (특수 지침 섹션 포함)
- 사용자가 선택/확정한 구조
- lessons/01/input.md 내용
- 리서치 결과 요약
- 주 원천 자료가 있으면 해당 sources/ 파일 발췌본과 자료목록.md의 사용 지침 — 본문은 원천 자료에 근거해 작성할 것
- 분량 기준 (project.md에 명시된 값, 기본 A4 2~3장/2,500~4,000자)
- 성경 인용은 개역개정만 사용

lesson-writer는 `lessons/01/draft.md`, `lessons/01/worksheet.md`, `lessons/01/teacher-notes.md`를 작성한다.

## 5. 평가

1과에 대해 `/evaluate-lesson` 흐름을 실행한다: lesson-evaluator 서브에이전트를 실행해 `lessons/01/evaluation.md`를 생성한다.

80점 규칙을 적용한다.

- 점수 80점 미만: lesson-updater 서브에이전트를 실행해 자동으로 수정하고 재평가한다. 최대 3회 반복한다. 3회 후에도 80점 미만이면 사용자에게 상황을 보고하고 지시를 기다린다.
- 점수 80점 이상: 자동으로 수정하지 않는다. 개선 제안을 사용자에게 제시하고 사용자의 지시를 기다린다.

## 6. 승인 및 스타일 규칙 추출

사용자가 명시적으로 승인하면:

1. `lessons/01/draft.md`를 `lessons/01/approved.md`로 복사한다.
2. `style/style-rules.md`를 작성한다 (`templates/style-rules.md`가 있으면 그것을 채운다). 다음을 approved.md에서 실측하여 구체적으로 기록한다.
   - 문체 (어미, 존댓말 여부)
   - 제목/소제목 패턴
   - 섹션 구성과 순서
   - 섹션별 글자 수 (기준 분량으로 기록 — 반드시 실제 수치)
   - 문단 길이
   - 질문 유형과 개수
   - 활동 형식
   - 교사용 해설 톤
   - 자주 쓴 표현
   - 금지 표현
3. `style/next-lesson-notes.md`를 작성해 다음 과 집필 시 참고할 점을 정리한다.
4. `project.md`의 과별 진행 현황표에서 1과 상태를 "승인"으로 갱신한다.

## 7. 안내

작업을 마치면 사용자에게 다음 단계는 `/write-lesson 2`(2과 집필)임을 안내한다.
